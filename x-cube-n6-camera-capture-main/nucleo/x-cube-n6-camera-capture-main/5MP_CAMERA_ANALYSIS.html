5MP Camera Capture Feasibility Analysis

STM32N657X0-Q Nucleo Board + B-CAMS-IMX (IMX335) Camera

Executive Summary

Feasibility Status: ❌ NOT FEASIBLE on NUCLEO-N657X0-Q without external RAM

Capturing 5MP (2592×1944) images from the IMX335 sensor on the NUCLEO-N657X0-Q board is NOT FEASIBLE in its current configuration due to critical memory limitations.

Critical Finding: No Onboard PSRAM

The NUCLEO-N657X0-Q does NOT have onboard PSRAM. The available memory is:

Memory Type Size Usable for Camera
Main SRAM 4.2 MB ~2.5 MB (after system overhead)
Data TCM 128 KB Limited use
Instruction TCM 64 KB Not usable for data
Backup SRAM 8 KB Not usable
Onboard PSRAM NONE ❌

Total Available for Frame Buffers: ~2.5 MB maximum

This is INSUFFICIENT for any 5MP capture scenario.

3. Bus Bandwidth Analysis

3.1 Camera Data Path 

IMX335 Sensor (MIPI CSI-2)
         ↓
    DCMIPP Interface
         ↓
    AXI Bus (400 MHz)
         ↓
    PSRAM / SRAM

Data Rate Calculation for 5MP @ 30fps:

  • RAW10: 2592 × 1944 × 1.25 bytes × 30 fps = 236 MB/s
  • YUV422: 2592 × 1944 × 2 bytes × 30 fps = 302 MB/s

AXI Bus Capacity:

  • AXI clock: 400 MHz
  • Bus width: 320-bit (40 bytes) per cycle
  • Theoretical: 400 MHz × 40 bytes = 16 GB/s
  • Sufficient for camera data transfer

4. Critical Bottlenecks Identified

🔴 Critical Bottleneck #1: PSRAM Size Unknown

The NUCLEO-N657X0-Q datasheet does not clearly specify the PSRAM size. Without at least 16 MB PSRAM, 5MP capture is impossible.

🔴 Critical Bottleneck #2: USB Bandwidth

USB 2.0 cannot stream 5MP raw frames at usable frame rates. Maximum achievable:

  • Raw/YUV: ~5 FPS (with heavy compression/quality loss)
  • JPEG: 15-30 FPS (with compression)

🟡 Moderate Bottleneck #3: Memory Allocation

Current code allocates only 768 KB per buffer (800×480×2). Must be increased to 10+ MB.

🟡 Moderate Bottleneck #4: Buffer Count

Only 2 buffers allocated. For smooth operation at high resolution, 4+ buffers recommended.

7. CRITICAL Recommendations

For 5MP Capture - You MUST Choose One:

Option 1: Add External PSRAM (Recommended for Nucleo Users)

Connect external PSRAM/HyperRAM via the XSPI pins on ST Morpho headers:

Required Components:
├── HyperRAM chip (IS66WVS8M16 or similar)
│   └── 8M x 16-bit = 16 MB recommended
├── XSPI interface on STM32N6
│   └── Uses XSPI1 or XSPI2 pins
└── Proper PCB layout for high-speed signals

Pins needed (XSPI1 example):
- XSPI1_CLK (PB2)
- XSPI1_D0/QSPID0 (PD11)
- XSPI1_D1/QSPID1 (PD12)
- XSPI1_D2/QSPID2 (PE7)
- XSPI1_D3/QSPID3 (PE8)
- XSPI1_D4/QSPID4 (PE9)
- XSPI1_D5/QSPID5 (PE10)
- XSPI1_D6/QSPID6 (PE11)
- XSPI1_D7/QSPID7 (PE12)
- XSPI1_NCS/QSPICS (PB10)

Result: With 16 MB external PSRAM, 5MP JPEG becomes fully feasible.

Option 2: Switch to Discovery Board

Use STM32N6570-DK (MB1941) instead of Nucleo:

  • Includes onboard PSRAM (typically 16-32 MB)
  • Full camera shield support (B-CAMS-IMX)
  • Ready for high-resolution capture
  • No additional hardware needed

Option 3: Use Lower Resolution

Accept VGA (640×480) or WVGA (800×480) maximum:

  • Fits within 4.2 MB SRAM
  • 30 FPS achievable
  • Suitable for AI inference, basic vision
  • Not suitable for high-quality imaging

If Staying with Nucleo + 5MP Goal:

  1. Design Custom Shield

    • Add HyperRAM module to Arduino/Morpho headers
    • Configure XSPI interface in software
    • Update memory allocation in code

  2. Use External Storage Only

    • Capture directly to Octo-SPI Flash (64 MB available)
    • No frame buffer needed in RAM
    • Read out images later via USB
    • Very low FPS, but works with current hardware

  3. Hybrid Approach

    • Use camera for AI inference at low resolution (VGA)
    • Trigger high-res capture only when needed
    • Store to flash, not RAM
    • Transfer compressed images via USB

9. FAQ: What If I Only Work with Raw Data Internally?

Question: If I don't need to stream/display images, can I use the existing 4.2 MB SRAM for 5MP raw capture?

Answer: NO - You STILL need external memory

Even if you only process raw data internally without streaming or displaying, you still cannot fit a 5MP frame in the available SRAM.

The Math: 

Single 5MP RAW10 Frame Size:
├── Resolution: 2592 × 1944 pixels = 5,039,616 pixels
├── Bit depth: 10 bits per pixel
├── Bytes per pixel: 10/8 = 1.25 bytes
└── Total: 5,039,616 × 1.25 = 6,299,520 bytes = 6.3 MB

Available Memory:
├── Total Internal SRAM: 4.2 MB
├── System Overhead (FreeRTOS, Code, Stack): ~2.3 MB
└── Available for Frame Buffer: ~1.9 MB ❌

Result: 6.3 MB needed > 1.9 MB available

Why You Still Need External Memory:

  1. Single Frame Exceeds Total SRAM: A single 5MP RAW frame (6.3 MB) is larger than the entire 4.2 MB internal SRAM, not just the available portion.

  2. Camera Requires Continuous Buffer: The DCMIPP camera interface needs a pre-allocated memory region to write pixel data. It cannot write to memory that doesn't exist.

  3. Processing Requires Memory: Even if you just want to run AI inference on the raw frame, the neural network weights and intermediate tensors need additional memory.

What IS Possible with 4.2 MB SRAM:

Resolution RAW10 Size Feasible? Notes
640×480 (VGA) 384 KB ✅ Yes Plenty of room for multiple buffers
800×480 (WVGA) 480 KB ✅ Yes Good for AI inference
1280×720 (720p) 1.2 MB ⚠️ Tight 1 buffer only, no headroom
1920×1080 (1080p) 2.6 MB ❌ No Exceeds available memory
2592×1944 (5MP) 6.3 MB ❌ No Larger than total SRAM

Alternative: Direct-to-Flash Capture (Advanced)

The STM32N6 has 64 MB Octo-SPI Flash that could theoretically store 5MP frames directly:

Pros:
├── No external RAM needed
├── 64 MB available (enough for ~10 RAW frames)
└── Works with current hardware

Cons:
├── Very slow write speeds (~10-20 MB/s)
├── Cannot do continuous capture
├── Limited flash endurance
├── Complex implementation required
└── Not suitable for real-time AI processing

Verdict: While technically possible, direct-to-flash capture is not practical for most applications.

Bottom Line:

For 5MP raw capture, you MUST add external memory regardless of whether you stream/display the data. The 4.2 MB internal SRAM is fundamentally insufficient for a single 5MP frame.

Minimum Recommendation: Add 16 MB HyperRAM via XSPI interface for practical 5MP operation.
